# 产品需求

## 概览

SIG 把值得阅读的新闻、人物动态、长文和可参加的活动放在一个个人空间；sig 协助理解信息，并通过对话管理偏好。首版只供用户个人使用。

## 已确认的核心范围

| 模块 | 要求 |
| --- | --- |
| 新闻领域 | AI、科技、GitHub、金融、中美政治、体育、影视 |
| 内容类型 | 新闻、精选文章、名人动态 |
| 阅读深度 | 深度版；列表摘要、详情重点、AI 分析与评价、可追问 |
| 来源 | 原文链接可直接打开；正文入口打开站内摘要详情 |
| 早晚报 | America/Los_Angeles 每天 09:00、21:00；晚报不重复白天内容 |
| 头版 | 七领域各一条，横向轮播；缺乏可靠内容时不能为了凑数编造 |
| 活动 | 演出、比赛、社交活动、展览与放映；地点/范围/日期/预算可手动编辑 |
| 默认活动范围 | 洛杉矶市中心周边 60 miles，按直线半径；当前时刻起未来一个日历月 |
| 偏好管理 | 对话优先，避免复杂设置页；常用筛选保留直接操作 |
| 助手 | 常驻可收起，关联当前文章，切换页面不应抹掉已有对话 |

## 当前实现程度

| 能力 | 原型已有 | 正式版未完成 |
| --- | --- | --- |
| 早晚报 | 不同主题、不同演示条目 | 数据生成、日程调度、推送、去重 |
| 内容阅读 | 列表/详情/参考链接 | 真实检索、全文提取、核实、摘要生成 |
| 稍后阅读 | 内存 Set 收藏 | 服务端保存与跨会话恢复 |
| 助手 | 预设回复、少量关键词操作 | 模型调用、检索引用、流式回复、偏好理解 |
| 活动 | 表单、分类、日期校验、提示 | 地理编码、活动检索、价格距离筛选 |
| 每日鼓励 | 按洛杉矶日期轮换固定原创句子 | 无需为了此功能强制引入模型 |

## 信息质量要求

以下是正式版建议，应在实现前具体化来源清单与排序规则：优先官方原始资料、项目仓库/发布记录、可靠媒体；保留标题、发布/更新时间、来源和可访问链接。区分事件事实、来源观点与 AI 推断，证据不足应明确表达。

晚报去重至少考虑规范化 URL、转载/同事件聚类、早报已投递集合，不能只比较标题。对同一事件的重大新增进展是否例外作为「更新」呈现，待用户决定。

真实活动应包含时间与时区、场地、距离、票价与币种、售票/取消状态、官方链接和最后核查时间；无法确认票价不能当免费。

## 非本轮范围与待定

未要求多用户社交、广告、订阅收费、原生 App、完整后台 CMS。登录方式、预算费用上限、数据源、模型、推送渠道均未确定。用户要求定时收到内容，但具体通过站内/邮件/系统通知等何种渠道尚需确认。

## 总结

设计已认可；数据与 AI 服务尚未实现。优先完成可靠的个人阅读闭环，随后接入采集、对话和定时分发。
